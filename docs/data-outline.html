Data outline

Explore what Skippy stores, from the main information types to individual fields. Open any section for more detail. This outline uses the unified Knowledge model and keeps standalone Tasks at the same level as Projects.

Reading the model: Field names match convex/schema.ts. Each field is marked required or optional. Dates and times are generally numbers representing milliseconds since the Unix epoch; other numbers represent scores, counts, amounts, or positions.

Every record also has an automatic _id (unique ID) and _creationTime (creation timestamp). These are additional to the fields listed below. References point to another table; lists can contain values or nested objects. Application functions may enforce additional rules beyond this schema.

Knowledge knowledge30 fields

Unified storage for notes, links, structured knowledge objects, and memories.

Four kinds of Knowledge
  • Notes kind: note

    Freeform written information.

  • Links kind: link

    Saved URLs with context, summaries, and reading or saving status.

  • Knowledge objects kind: knowledgeObject

    Structured information with a flexible objectType and properties.

  • Memories kind: memory

    Classified using memoryType:

    • thought
    • memory
    • decision
    • principle
    • question
    • insight
    • artifact

    An “artifact” memory is a Knowledge classification. A stored deliverable file has its own Files and artifacts record.

The fields below are shared by this table; their relevance depends on the record’s kind. Schema optionality does not mean every combination is accepted by application write functions.
