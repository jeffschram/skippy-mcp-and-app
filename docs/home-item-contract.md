## Canonical identity and deduplication

Use a discriminated reference `{kind: 'task' | 'event' | 'recurrence', id}` with table IDs from `tasks`, `calendarEvents`, and `recurrences`. Row key is `${kind}:${id}`. Event external IDs, URLs, title/date combinations, list indices, attention/feed keys, and DOM hashes are not mutation IDs. Resolve kind and ownership server-side. Keep recurrence identity outside the existing knowledge `entityRef` union, as the current model does.

The normalized row contains this reference, title, status, commitment/area, effective date, all-day flag, available links, and capabilities. A spawned task additionally carries `recurrenceId`, recurrence status, and an occurrence version. Capabilities are derived from the fresh owned records, not inferred from a title or trusted as client authorization. Detail data is loaded separately on demand.

1. Deduplicate exact table IDs first. Resolve recurrence `currentTaskId` against the complete owned relationship, before date, area, project, or pagination filtering. A live task represents that occurrence; suppress the schedule row even when that task is outside the current period. Preserve both IDs on the task projection. Never fuzzy-match recurrences.
2. A missing, foreign, done, or cancelled `currentTaskId` must not permanently suppress the recurrence. Treat it as stale, surface the active schedule once, and repair through an owned mutation. Do not write during a query. Resolve paused as well as active recurrence links so their spawned tasks remain identifiable.
3. Current `agendaItemsAreDuplicates` heuristically collapses event/event and event/task pairs with equal timestamps and similar titles, preferring events. This can hide actionable tasks. The new contract uses canonical identity and explicit recurrence linkage only for destructive suppression. Keep distinct event/task IDs visible unless an explicit relationship establishes equivalence; even then preserve access to both records/actions. Similar titles alone never transfer completion to an event. This deliberately tightens the existing display heuristic.
4. Deduplicate before counts and within each inventory, including across page boundaries. All is the complete inventory, so an item may also appear in a bounded card; these are reactive projections of the same ID, never separate copies or separate completion targets. Today and This Week do not overlap.

Evidence: `apps/web/app/hubs/agenda-rows.ts:101` (`buildAgendaRows`); `packages/shared/src/agenda.ts:65` and `:134`; `convex/agenda.ts:37`; `convex/lifeTasks.ts:52`; `convex/recurrences.ts:147`. Today’s lifecycle hole is real: `setLifeTaskStatus` marks a spawned task done without advancing its recurrence, and the firing job can spawn another task for that unchanged due occurrence.

## Inclusion rules

Use one captured clock and browser IANA timezone (UTC fallback) across all cards, with refresh at local midnight, timezone changes, and return to the page. Compute civil-day boundaries with timezone-aware calendar arithmetic, not multiples of 86,400,000 ms. Proposed week convention is Monday–Sunday; label the displayed dates so the cutoff is unambiguous. Use half-open ranges `[start, end)`.

| Inventory | Included | Excluded or reachable elsewhere |
| --- | --- | --- |
| Today | Open personal must-tasks due on the local date; active recurrences due on that date; ongoing and upcoming events overlapping that date. A separate overdue group covers the preceding seven local dates. | Undated tasks, wants, farther-future items, and older overdue work stay in All. Show an All affordance explaining older overdue items may remain. |
| This Week | Tomorrow at local midnight through next Monday at local midnight; dated personal must-tasks, active recurrences, and non-ended events. Empty on Sunday after Today; do not silently switch to a rolling seven-day horizon. | Today/overdue rows, undated tasks, wants, and later weeks. |
| All | Every accepted non-project open task, including all overdue dates, far-future deadlines, undated obligations, waiting tasks, and wants. All active recurrence schedules regardless of next date. Current/upcoming events covering at least the former Agenda horizon, with continuation beyond it. | Done/cancelled tasks and paused/retired schedules are separate status filters; ended/cancelled events are not the planning inventory. Project work remains in Projects. |

Today and This Week each render at most 20 normalized rows, oldest overdue first then chronological, with an explicit “More in All” overflow affordance. This bounds presentation; the data reads must also be bounded. All starts with 50 rows and Load more, never a client-side slice of a full collection. All sorts dated obligations/events first, undated must-tasks next, wants last; within a group use date, title, then canonical key for deterministic ties. Preserve area filtering, including Unsorted; events remain visible under every area filter, matching the former Agenda. Name the reset “All areas” to distinguish it from the inventory.

All’s default calendar horizon is ongoing events plus starts through 365 local days ahead, preserving the old `life-tasks.tsx` range of approximately one year. Offer a continuation into later date windows without removing previously reachable records. Include ongoing events that began before the old seven-day lookback. Do not equate All with the seven-day agenda API. Calendar recurring instances use their mirror row IDs; do not manufacture future instances or render recurrence masters as appointments.

Wants always have no effective date and never become overdue, even with malformed legacy `dueAt`; absent commitment means must. New writes must enforce that invariant. Waiting is still open: dated waiting tasks follow periods; undated waiting tasks remain in All. A task linked to a project leaves all personal inventories immediately, but its modal/deep link stays resolvable and offers the project link. A recurrence represented by that project-linked task stays suppressed until the occurrence ends; subsequent recurrence occurrences remain personal unless separately redesigned.

Done/cancelled tasks are hidden by default. All offers Completed/cancelled and Paused/retired filters so history, paused schedules, and legacy deep links remain reachable without polluting Today/This Week. Pausing prevents future firing but does not cancel an already spawned task: that task remains open and displays “Repeat paused”; its details permit Resume. A paused schedule with a live task is represented by that same task in the paused filter. Completion history is shown in recurrence details, not as duplicate agenda rows. Existing history is capped at 24; label it “Recent history,” not lifetime history.

Timed events use overlap (`startAt < end && endAt > start`) and disappear after their end; events are never overdue. All-day events use their UTC-encoded calendar dates and exclusive end date without shifting into yesterday in the viewer zone. Missing legacy end falls back to start for expiry. Recurrence placement uses `nextDueAt`, not lead-time surfacing; a pre-created spawned task uses its deadline. These are explicit decisions, including DST and ongoing-event corrections to current start-only/inclusive queries.

## Required backend gaps

**G1 — Owned detail.** Add proposed `homeItems.getForViewer({kind,id})`, normalize the ID against its table and require the session’s brain. Return a typed record, available source links, parent project, live recurrence/task association, occurrence version, and capabilities. Return null for unavailable/foreign IDs without exposing another account. Fetch archived/completed records by ID even when absent from lists. Task `attention.getForViewer` returns status/source links but not full description; `getTaskBriefForViewer` is task-specific. Neither is a three-type detail endpoint.

**G2 — Bounded inventory.** Add period and All queries with server-enforced limits, opaque continuation, frozen range/clock/filter parameters and stable canonical tie-breaks. Page each indexed source with bounded work, then merge with a cursor retaining unconsumed source heads; do not `.collect()` and slice. Project exclusion, recurrence claims and paused association need indexed point lookups. Add indexes/maintained linkage where needed, including recurrence lookup by current task and event overlap access. Ensure filtering can return a short page with a continuation without falsely reporting exhaustion. A period response returns rows plus `hasMore`, not a fabricated exact count. Tests must prove page boundaries do not duplicate or lose items and that undated/want groups remain reachable. Existing list APIs are reference semantics, not a pagination implementation.

**G3 — Atomic occurrence lifecycle.** Add an occurrence/version token advanced on completion, skip and schedule edit; carry it in rows and mutations. Add an owner-checked action accepting `{recurrenceId, expectedOccurrenceVersion, action:'complete'|'skip', requestId, completedAt?, note?}`. Persist idempotency outcome; replay returns the first result, a different stale request fails without advancing again. Validate live task ownership. Atomically update that task, recurrence, history and version. Route spawned completion/cancel from Home, Mind and chat-backed task APIs through the same transition so another surface cannot bypass it.

Completion retains `computeNextDue` semantics: completion anchor restarts from actual completion, schedule anchor advances to the first future slot without replaying missed periods. Skip leaves `lastCompletedAt` untouched, cancels the live task, and advances from the scheduled occurrence to the first slot after `max(now, oldNextDueAt)` for either anchor. Record `{outcome:'skipped', occurredAt, scheduledFor, taskId?}` separately from completion. Extend history compatibly: legacy `{completedAt,note}` means completed. Preserve the existing 24-entry cap and all existing entries within it; never fabricate older history.

Add a version-checked schedule patch for cadence/anchor/timezone/explicit next date. An explicit next date overrides recalculation for this occurrence; future occurrences follow the rule. If a live task exists, update its due date atomically, retain its ID, and preserve its description/status. Editing a spawned task deadline invokes that same operation; clearing its deadline is unavailable while it represents a scheduled occurrence. Clearing remains supported for ordinary tasks. Resume retains nextDueAt, so overdue items return visibly. Backfill durable task→recurrence/occurrence provenance for live associations; old completed tasks without provenance cannot reliably be reconstructed from titles.

**G4 — Write invariants.** Harden reused task writers: reject blank trimmed titles/non-finite dates, clear deadline when converting to want and reject want-plus-deadline creation. Check the waiting target belongs to the same brain; current `setWaitingOn` only verifies the task. Completion must preserve dependency/attention behavior and recurrence history consistently. These are targeted extensions, not a new generic mutation framework.

**G5 — Context enrichment.** Preserve the existing Mind chat resolver; extend its bounded allowlist with recurrence rule, anchor, timezone, live task reference and recent completion/skip outcomes, and task recurrence provenance. Currently those fields are mostly absent from `FIELDS`. Resolve linked records with ownership checks. No new chat table, runner transport, or event entityRef variant is needed.

## Shared row, modal and conversation

Extract `HomeItemRow`, `HomeItemActions`, and `HomeItemDialog` (proposed names). Use a semantic list; title is a real button opening details. Completion and overflow menu are sibling controls, never nested in the title button or an anchor. Support Enter/Space, visible focus, explicit accessible labels, 44px touch targets, wrapping text and no hover-only actions. Pending state is keyed to canonical reference plus occurrence, shared across projections; disable repeated submission, announce success/error, and keep failed edits retryable. Server idempotency remains necessary despite client disabling.

Reuse the Dialog primitive in `apps/web/app/components/widgets.tsx:112` (Shad/Radix Dialog) for labelled modal semantics, focus trapping and Escape. Mind’s detail wrapper in `apps/web/app/mind/mind-content.tsx:320` is an `aside` with swipe behavior, not a complete accessible modal to copy. Reuse its content/chat composition, not that shell. Restore focus to the opener or nearest surviving row/section after completion. On mobile use a full-width viewport-bounded sheet, visible close button, independently scrollable details/transcript, safe-area padding and a composer reachable above the keyboard. Swiping is optional, never required. Opening focuses the heading/close control, not automatically the chat keyboard. Distinguish loading, unavailable, fetch error/retry, and empty history.

`MindCardChat` at `apps/web/app/components/chat-panel.tsx:940` keys `ChatSurface` by item ID and uses page scope `mind-item:<raw canonical ID>`. Keep that exact pageKey so Home and Mind share the established transcript. Carry `{kind,id}` in the Home adapter and validate the kind through G1; do not change the pageKey to `home-item:*` or append kind without a migration. Convex table IDs already distinguish types. A spawned-task modal chats about its task ID; “View repeating schedule” explicitly selects the recurrence ID and its separate conversation. Never silently switch the conversation when completing a task or when the next task spawns.

Extract a neutral item-chat wrapper around the existing ChatSurface to avoid Mind-only CSS and global-card state assumptions. Remount on canonical selection; clear stale detail/draft presentation and ignore previous-item asynchronous results. Read transcripts only for the current scope. On deletion/unavailability disable sending and do not substitute a similarly named item. Page-chat attachments are currently rejected; do not expose an upload affordance without separately scoped support.

Verified server chain: `convex/chats.ts:199` reads brain-scoped conversations; `:268` validates Mind scope before sending; `:381` validates when starting anew; `:506` refreshes context when claiming a turn. `convex/mindChatContext.ts` resolves tasks/calendarEvents/recurrences with `normalizeId`, checks brain ownership, and provides bounded record/source/relationship context. The client label is display text, not authoritative context. Preserve existing harness history, approvals and completion behavior.

Legacy `/tasks#task-<id>` and `/tasks#recurrence-<id>` navigate to Home while retaining the hash; add `#event-<id>` for canonical event links. A shared hash resolver opens G1 directly, bypasses list filters for the selected record, and exposes a project link if it moved. Missing records show an unavailable state, never an empty successful redirect. Browser Back closes/restores selection without losing All pagination.
